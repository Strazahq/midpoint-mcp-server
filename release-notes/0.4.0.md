This release adds interactive approval and access views, safer approvals, support for agents that sign in as themselves, and signed release artifacts with Kubernetes manifests.

## What's new

- Four interactive views for MCP clients that support MCP Apps: Requests to approve, Get access, My requests and My team's access. They are built into the binary and use no network or storage of their own. They pass their browser test suites but have not yet been tried against a live midPoint.
- A new `decide_work_item` tool approves or rejects a work item. Before writing anything it checks that the item is open and assigned to the caller, and afterwards it reports what midPoint recorded.
- Agents and services that sign in with the OAuth client credentials grant can now act as a midPoint user, limited to the archetypes you list.
- The first part of team self-service: `list_my_teammates` and `whoami`.
- Every error result carries a stable error code, and errors no longer reveal midPoint's address.
- An optional settings file for non-secret configuration, OIDC discovery from a separate URL, and optional anonymous discovery of the tool list.
- The server now stops cleanly on SIGTERM and lets requests in flight finish, so Kubernetes, Docker and systemd restarts no longer cut them off.

## Breaking changes

- `approve_work_item` and `reject_work_item` are removed. Call `decide_work_item` with `decision` set to `approve` or `reject`.
- `request_role` now refuses roles that midPoint does not offer for request.
- The Go module path is now `github.com/strazahq/midpoint-mcp-server`. This only matters if you import the code.

## Before you upgrade a shared deployment

- The service account must be able to search users on the attributes the server matches tokens against. The example role `examples/role-mcp-rs-service.xml` does not grant that on its own. See `docs/authorization.md`.
- Read `docs/misconfigurations.md`. It lists the settings that can let one caller act as another, or lock everyone out.

## New documentation

- Step-by-step setup with Keycloak and with Microsoft Entra ID as the identity provider, with midPoint as the system that owns the users: `docs/identity-providers.md`.
- Ready-to-fill configuration files: `examples/keycloak.env` and `examples/entra.env`.

## Install

- Binaries for Linux, macOS and Windows are attached below.
- Container image: `ghcr.io/strazahq/midpoint-mcp-server:0.4.0`, for amd64 and arm64.
- Kubernetes: apply the attached `midpoint-mcp-server-kubernetes.yaml` after creating the Secret, as described in `deploy/kubernetes/README.md`.

## Verify what you downloaded

Every artifact is signed with Sigstore by this repository's release workflow, and each comes with an SPDX SBOM and a build provenance attestation.

```sh
cosign verify-blob checksums.txt \
  --bundle checksums.txt.sigstore.json \
  --certificate-identity-regexp '^https://github\.com/Strazahq/midpoint-mcp-server/\.github/workflows/release\.yml@refs/tags/v' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
sha256sum -c checksums.txt --ignore-missing
```
