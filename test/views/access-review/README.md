# My team's access checks

Run `node test/views/run.mjs --suite access-review` from the repository root.
The suite uses the shared fake MCP Apps host and Chromium runner, with its own
allowlist, catalog strings, named mutations, and run-wide protocol and sandbox
checks. Each acceptance criterion of contract 7.4 has named checks; shared
checks cover the lifecycle, modes, errors, preview, intermediary decisions,
keyboard, contrast, sizing and security.

Fixtures are generated by this server in UI sessions against a local fake
midPoint, using recorded-style REST answers in `internal/midpoint/testdata`:

```sh
MIDPOINT_MCP_WRITE_VIEW_FIXTURES=1 go test -run TestWriteAccessReviewViewFixtures .
```

`view_fixtures_access_review_test.go` documents the recordings and additions.
`TestAccessReviewToolResults` exercises the same scenarios during ordinary Go
tests, including the exact assignment deletion body and the write gate.
Generated results live in `../fixtures/access-review.*.json`; exceptional host
and data conditions come from named mutations in `derive.mjs`.

Live verification remains necessary on midPoint 4.10 for a manager's
approval-gated removal and subsequent case visibility/read-back. The harness
proves the client/server behavior for those shapes, not the deployment's
permissions or policies.
